# УПК — Цифровой помощник колледжа

Адаптивное веб-приложение для демонстрации процесса регистрации и обработки обращений в колледже. Интерфейс на русском языке, дизайн в тёмно-синих, голубых и белых оттенках.

## Быстрый запуск

1. Скачайте или клонируйте репозиторий.
2. Откройте `index.html` в браузере.
3. Для публикации откройте репозиторий GitHub → **Settings → Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**, ветку `main`, папку `/ (root)`, затем нажмите **Save**.
5. Через несколько минут сайт станет доступен по адресу `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Сборка и установка зависимостей не требуются.

## Демо-доступ сотрудника

- Логин: `upk`
- Пароль: `upk2026`

Это только демонстрационный вход на клиентской стороне. Он **не является безопасной авторизацией** и не должен использоваться для реальной эксплуатации или хранения персональных данных.

## Что реализовано в демонстрации

- Адаптивная форма создания обращения.
- Категории, корпус и кабинет, описание и выбор изображения (файл проверяется, но в демо не загружается на сервер).
- Уникальный номер и случайный код отслеживания.
- Просмотр статуса, комментариев и истории по номеру и коду.
- Панель сотрудника: поиск, фильтрация, назначение исполнителя, изменение статуса, комментарии.
- Обязательный итоговый комментарий при статусах «Решена» и «Отклонена».
- Три демонстрационные локации и QR-ссылки с параметром `?room=214`.
- Статистика по заявкам и категориям.
- Правиловый демонстрационный помощник: типовые ответы, неисправности, неизвестные вопросы и опасные ситуации.
- Начальные демонстрационные обращения.

## Важное ограничение текущей версии

Сейчас данные хранятся в `localStorage` браузера. Это означает:
- данные видны только в том браузере и на том устройстве, где были созданы;
- разные посетители сайта не видят общую базу;
- очистка данных браузера может удалить демонстрационные заявки;
- вход сотрудника — демонстрационный, без серверной проверки прав;
- помощник использует заранее заданные правила и локальные ответы, а не внешнюю языковую модель;
- фотографии не передаются в хранилище.

Поэтому этот вариант подходит для демонстрации интерфейса и сквозного сценария на защите, но не является готовой системой для реальной эксплуатации колледжем.

## Как получить общую базу и безопасную авторизацию

Для публичного проекта подключите серверную часть (например, Supabase или собственный backend):
1. Создайте проект Supabase.
2. Создайте таблицы заявок, пользователей, комментариев, истории, категорий и помещений.
3. Включите Row Level Security (RLS) и настройте политики доступа: заявитель видит только своё обращение по защищённому токену; сотрудник — только после серверной авторизации и проверки роли.
4. Храните хеш токена отслеживания, а не открытый токен.
5. Фотографии загружайте в закрытое хранилище с ограничением типа и размера; выдавайте временные ссылки.
6. Все привилегированные операции выполняйте на сервере. Не помещайте `service_role`, пароли, секреты или ключи языковой модели в `index.html`, `config.js` или публичный репозиторий.
7. Для реального ИИ обращайтесь к модели через серверный endpoint, а не напрямую из браузера.
8. Перед запуском настройте резервное копирование и проверьте все роли и сценарии доступа.

## Проверка сценариев из ТЗ

| Сценарий | Как проверить |
|---|---|
| Создание заявки | «Новое обращение» → заполнить поля → зарегистрировать |
| Уникальный номер | После отправки отображается номер и код |
| Отслеживание | Вкладка «Мои заявки» → номер и код |
| Панель УПК | Войти с демо-доступом |
| Поиск и фильтры | Использовать строку поиска и выпадающие списки |
| Назначение и статус | Открыть заявку, указать исполнителя и новый статус |
| История | Сохранить изменение и посмотреть историю в карточке |
| Типовой вопрос | Помощник: «Как подключить ноутбук к проектору?» |
| Неисправность | Помощник: «В кабинете 214 не работает проектор» |
| Опасность | Помощник: «В розетке искрит» |
| Неизвестный вопрос | Задать вопрос, отсутствующий в базе |
